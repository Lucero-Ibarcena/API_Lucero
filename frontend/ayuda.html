Red de registro y búsqueda de mascotas

API para perfiles de mascotas, búsqueda, avisos de pérdida, adopción, contacto con autorización y servicios en el mapa.

Empezar

Las rutas aceptan y devuelven JSON. Crea una cuenta con POST /usuarios; guarda el token que devuelve y envíalo en las rutas privadas como Authorization: Bearer TU_TOKEN.

{
  "nombre": "Ana Pérez",
  "email": "ana@example.com",
  "contrasena": "una-frase-larga-y-unica",
  "pais": "Argentina",
  "localidad": "CABA"
}

La contraseña debe tener al menos 12 caracteres. Se puede iniciar sesión en POST /usuarios/login, ver el perfil en GET /usuarios/me y cerrar sesión en POST /usuarios/logout.

Mascotas

Método y rutaAcción
POST /mascotasRegistrar una mascota en el perfil autenticado. Requiere nombre y especie; inicia privada.
GET /mascotas/propiasListar las mascotas propias y compartidas.
GET /mascotas?especie=Perro&localidad=CABABuscar perfiles publicados con filtros combinables: nombre, especie, raza, edad, sexo, color, tamaño, estado, vacunación, localidad, provincia, país y responsable público.
PUT /mascotas/IDActualizar el perfil que administras.
POST /mascotas/ID/reportes/perdidaPublicar un aviso de pérdida con localidad aproximada.
PATCH /mascotas/ID/estadoCambiar a adopción, refugio, tránsito, encontrada u otro estado permitido.

El perfil admite raza, edad, sexo, tamaño, colores, señas, fotos, salud, identificación, comportamiento y ubicación. Las consultas públicas no muestran microchip, domicilio, coordenadas exactas, notas médicas privadas, email ni teléfono.

Compartir una mascota

El responsable principal puede invitar a una cuenta existente con POST /mascotas/ID/responsables enviando {"email":"cuidador@example.com","rol":"cuidador"}. Los roles admitidos son cuidador, refugio y tránsito. La persona invitada consulta GET /mascotas/invitaciones y acepta en POST /mascotas/ID/responsables/aceptar.

Contacto protegido

Una persona registrada envía POST /contacto/solicitudes con {"mascotaId":"ID","mensaje":"Quiero ayudar a encontrarla."}. El responsable puede revisar GET /contacto/solicitudes y aceptar o rechazar con PATCH /contacto/solicitudes/ID.

Al aceptar puede enviar {"decision":"aceptar","compartirContacto":false}. Solo si elige true, las partes autorizadas pueden consultar email y teléfono en GET /contacto/solicitudes/ID/contacto. El responsable puede revocar el acceso en cualquier momento con DELETE /contacto/solicitudes/ID/contacto.

Mapa de servicios

GET /lugares?categoria=veterinaria&localidad=CABA filtra los puntos del mapa. También se puede filtrar por guardia=true o por cercanía con latitud, longitud y radioKm.

Las cuentas pueden reportar veterinarias, guardias, tiendas, peluquerías, refugios, guarderías, escuelas, perreras u otros puntos con POST /lugares. La respuesta indica si el punto fue verificado.

Almacenamiento

SQLite guarda cuentas, sesiones, permisos, solicitudes y lugares. Los perfiles flexibles de mascotas usan una colección documental JSON local. Es una configuración de desarrollo de un solo servidor, sin servicios externos.

GET /estado informa si la API está disponible. Para iniciar localmente: npm install y npm start.
